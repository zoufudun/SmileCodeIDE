# Keil 工程导入与函数导航

用户已选择直接读取原 `.uvprojx`。文件菜单增加导入入口，保留现有打开目录入口。导入只读取配置，不转换或改写原工程。

这里的只读指原始 Keil 工程配置不被转换或写回；IDE 继续使用既有 `.smilecode/project.json` 侧车配置。工程根目录按成员相对路径向上推断，最多三级且不进入盘符根目录，项目搜索沿用现有目录范围行为，导航器独立覆盖所有显式成员及可解析依赖。

## 行为
- 项目视图保留 Project → Target → Group → File 的原始名称和顺序，文件可展开函数。
- 函数视图按文件名排序，显示工程中的 C/C++ 源文件、头文件以及能够从本地 include 路径解析的递归依赖头文件；展开显示函数名和参数，双击使用现有安全源码导航打开对应行。
- 解析多个 Target，函数视图汇总去重；不把目录节点当成真实文件夹执行重命名或删除。
- 文件路径相对 uvprojx 所在目录解析，兼容反斜杠、中文和工程外部文件。缺失文件保留并明确标记。XML 错误不替换当前工程。
- 工程配置变化后防抖重新读取；提供刷新操作。源码变更刷新已展开的函数，编辑器未保存缓冲优先。
- 保存导入文件路径以在下次启动恢复，切换普通目录和关闭工程时清除 Keil 视图状态。

## 结构
`keilproject` 负责有序 XML 模型及路径，`projectnavigator` 负责两个视图、延迟函数加载、依赖索引、变更监听。复用 CodeEditor 的符号解析算法，通过无 UI 副作用的静态接口返回符号。MainWindow 只负责导入、持久化与工程上下文/源码跳转。

## 范围
本次实现工程结构和代码浏览，不转换 ARMCC/ARMASM 编译选项或承诺 Keil 工程可直接由 GCC 构建。现有构建模块保持其兼容路径。

## 验证
QtTest 覆盖多 Target、重复分组、中文相对路径、缺失文件、错误 XML、文件顺序、函数定义/声明/注释及函数调用误识别、导航信号、配置刷新、目录切换。编译主程序并运行现有相关回归测试。实际 Fire_H7 样本作解析验证。
