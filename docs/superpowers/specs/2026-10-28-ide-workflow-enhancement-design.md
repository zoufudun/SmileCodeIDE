## 方案

采用现有 MainWindow → STM32DebugController → BuildManager / FlashProgrammer / GDB 引擎。相较于仅换图标，此方案解决实际操作失败；相较于重建工具链架构，此方案保持改动集中并复用现有能力。

- 控制器统一约束空闲、构建、烧录、调试启动、运行、停机状态。相同项目重复设置不重置状态；切换/关闭项目先终止当前任务。构建启动失败恢复空闲，清理也进入构建状态。
- 烧录信号在构造阶段连接一次，保留启动前错误和全部输出；完成及取消恢复状态。统一解析 J-Link、ST-Link、CMSIS-DAP 名称，使用芯片 Flash 起始地址。
- 主窗口菜单、工具栏与按钮采用统一状态更新。增加重建、取消当前任务、暂停调试入口；启动握手期间禁止单步。不允许构建或烧写期间更换目标。
- 延续现有 Qt 图标绘制方式，使用明确的锤子、芯片下载、调试虫、暂停、停止与单步图形，避免依赖含义不明的字体码点。图标覆盖工具栏、菜单、主操作按钮。
- qmake VERSION 作为版本来源，应用元数据、IDE 应用卡和关于对话框保持一致，并生成正确的 Windows 文件版本。
