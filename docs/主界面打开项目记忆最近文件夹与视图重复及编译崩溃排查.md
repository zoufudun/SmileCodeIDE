# 专题归档：主界面打开项目记忆最近文件夹与视图重复及编译崩溃排查

## 一、 问题描述与现象
- **现象一（工程打开目录无法记忆）**：
  用户在点击主工具栏的【打开项目】时，每次弹出的文件选择对话框都重置到软件安装目录或初始写死路径，必须一层层手动翻找上一次正在编辑的工程文件夹，操作极其繁琐。
- **现象二（菜单栏“视图”重复出现两次）**：
  在主窗口菜单栏中，【视图】菜单出现了两个相邻的重复项，影响界面整洁度。
- **现象三（点击编译偶发退出崩溃）**：
  在快速连续点击【编译】或者工具链探测未完成时点击编译，程序偶发直接崩溃退出。

---

## 二、 问题分析与定位

### 1. 打开项目无法记忆路径的根因
- 查看 [mainwindow.cpp](file:///k:/TOPFIRE/SmileCodeIDEUpdate/PhudonTools/mainwindow.cpp) 的原有实现：
  `onOpenProject()` 函数直接调用 `QFileDialog::getExistingDirectory(this, "选择工程目录", QString())`，第三个参数传入了空字符串，导致 Qt 每次只能回退到当前工作进程的启动目录（`QDir::currentPath()`），没有做任何用户使用历史的持久化记录。

### 2. 菜单栏“视图”重复的根因
- 主窗口 `MainWindow` 初始化时本身在菜单栏创建了一个“视图”菜单用于控制基础 DockWidget；
- 而插件 `STM32WorkbenchPlugin` 加载时，又通过插件接口向菜单栏注册了一个新的“视图”菜单，缺少重复检查机制与统一视图管理，导致界面出现两个并排的【视图】。

### 3. 编译退出崩溃的根因
- 经过 GDB 调用栈分析，崩溃发生在 `GdbServerManager` / `FlashProgrammer` 的异步 `QProcess` 进程回调中；
- 当上一个探测进程仍在后台运行而用户快速触发了新的操作时，原有的子进程指针被直接析构或重复赋值，触发野指针访问或信号槽悬挂。

---

## 三、 修改计划

1. **引入 QSettings 最近路径持久化**：
   在 `MainWindow` 维护一个 `m_lastOpenedProjectPath` 成员变量，并接入 `QSettings` 注册表/INI 文件存储。打开项目优先以此为默认路径，成功打开后立即刷新持久化存储。
2. **重构视图菜单合并与守卫**：
   在插件加载与 DockView 注册阶段增加名称与对象排重守卫，消除重复菜单。
3. **引入 ProbeProcessGuard 进程安全生命周期守护**：
   规范后台 `QProcess` 的异步回调与生命周期管理，在发起新任务前安全清理旧进程，防止并发竞争引发崩溃。

---

## 四、 具体修改措施

### 1. mainwindow.cpp 路径持久化记忆
在 [mainwindow.cpp](file:///k:/TOPFIRE/SmileCodeIDEUpdate/PhudonTools/mainwindow.cpp) 中新增持久化读取与写入：
```cpp
void MainWindow::onOpenProject()
{
    QSettings settings("SmileCode", "PhudonTools");
    QString defaultPath = settings.value("LastOpenedProjectDir", QDir::homePath()).toString();
    if (!QDir(defaultPath).exists()) {
        defaultPath = QDir::homePath();
    }

    QString dir = QFileDialog::getExistingDirectory(this, tr("选择项目工程目录"), defaultPath);
    if (dir.isEmpty()) {
        return;
    }

    // 成功打开后立即更新记忆
    settings.setValue("LastOpenedProjectDir", dir);
    m_lastOpenedProjectPath = dir;
    loadProject(dir);
}
```

### 2. mainwindow.cpp 菜单栏重复视图守卫
在菜单栏装载阶段增加查重过滤：
```cpp
QMenu *viewMenu = findMenuByTitle(tr("视图"));
if (!viewMenu) {
    viewMenu = menuBar()->addMenu(tr("视图"));
}
// 插件只向已存在的唯一 viewMenu 追加 action，不创建新菜单
```

### 3. 增加 ProbeProcessGuard.h 进程安全守护
在 [ProbeProcessGuard.h](file:///k:/TOPFIRE/SmileCodeIDEUpdate/Plugins/STM32WorkbenchPlugin/Core/ProbeProcessGuard.h) 中封装安全的进程启动与中断机制：
```cpp
class ProbeProcessGuard {
public:
    static void safeTerminate(QProcess *&proc) {
        if (proc && proc->state() != QProcess::NotRunning) {
            proc->kill();
            proc->waitForFinished(500);
        }
    }
};
```
在发起新的工具链探测、编译或烧录前，确保旧进程已被安全退出并解绑信号槽，杜绝空指针悬挂。
