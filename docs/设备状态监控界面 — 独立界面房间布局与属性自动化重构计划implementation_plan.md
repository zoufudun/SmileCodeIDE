# 设备状态监控界面 — 独立界面房间布局与属性自动化重构计划

本计划针对用户提出的最新设备监控界面布局需求，对设备所属界面、房间关联、自动排列、拖拽安全性及 TabBar 切换崩溃进行彻底重构。

---

## 🎯 新需求与设计架构

### 1. 独立界面隔离与双层区域划分 (`targetView`)
- 每个界面（界面1、界面2、界面3...）完全独立展示其包含的房间与设备。
- 每个界面内部划分为：
  - **上方：未放置区域**（未摆放设备停靠区）：仅展示属于当前界面、且未归属任何房间/坐标的设备卡片。如果当前界面的所有设备均已放置到房间中，该区域**自动隐藏**。
  - **下方：房间/场景画布区**：展示属于当前界面的房间以及置于房间中的设备卡片。

### 2. 设备属性扩展 (`targetRoom` 自动建房与整齐排列)
- 扩展 `DeviceBitMapping` 结构，增加 `targetRoom` (所属房间名称) 字段。
- **自动化房间联动**：
  - 当在设备属性中指定了“所属房间”（如“1号机房”）：
    1. 若当前界面中不存在该房间，**系统自动新建该房间**；
    2. 将设备自动归入该房间，并在房间内按序号**自动整齐网格排列**（如按每行 3 个排列）；
    3. 自动向 `m_deviceRoomPos` 写入计算后的几何坐标。
  - 若设备属性中“所属房间”为空：
    - 设备从房间中弹出，归还至当前界面的最上方未放置区域。

### 3. 彻底根治拖动与切换界面崩溃 (Layout 冲突修复)
- **根因分析**：旧代码在切换界面时对停靠区布局 `m_unplacedContainer->layout()` 重复 `takeAt(0)` 和 `addWidget()`，造成 Qt 控件与 QLayoutItem 重复绑定及栅格损坏，导致点击 Tab 切回时在绘图帧爆栈崩溃。
- **修复方案**：
  - 规范控件Parent的挂载顺序，在清空未放置区时彻底摧毁/重载 Layout，防止控件项被多个 Layout 交叉引用。
  - 增加防抖与指针保护，彻底解决拖动图标后切换界面崩溃、首部切尾部再切回首部崩溃的问题。
