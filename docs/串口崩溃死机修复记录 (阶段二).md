## Fix 5 — `QTextEdit` 数据堆积导致界面冻结 (UI Freeze)

**位置**: [setupUi()](file:///m:/TOPFIRE/SmileCodeIDE/STM32IDE/serialportplot.cpp#62-832) 第 314 行

当串口设置了较低的自动发生间隔（如 `10ms`）高速首发数据时，如果无约束地向 `QTextEdit` 中追加格式化 HTML，其后台引擎的内存缓存和实时排版需求将呈几何级数增长，很快 100% 榨干 CPU，导致其他耗时操作（如打开新串口或新建分屏）瞬间将整个 UI 彻底卡死。

```diff
  m_textReceive = new QTextEdit();
+ // Prevent unbounded growth that causes permanent UI freeze on rapid auto-sends
+ m_textReceive->document()->setMaximumBlockCount(1000);
  m_textReceive->setReadOnly(true);
```

加入最大渲染行树约束后，底层的内存使用和 DOM 树计算都将维持在安全常数级，无论运行自动发送多久，都不会造成界面的堆积卡顿。

## Fix 6 — 非阻塞 [openClosePort()](file:///m:/TOPFIRE/SmileCodeIDE/STM32IDE/serialportplot.cpp#1308-1372) 错误提示

**位置**: [openClosePort()](file:///m:/TOPFIRE/SmileCodeIDE/STM32IDE/serialportplot.cpp#1308-1372) 第 1363 行

当第二个试图打开已经被第一个占用的 COM 串口时，系统打开失败并会立即抛出 `QMessageBox::critical`。在默认模式下，该弹窗会阻塞主线程当前的执行流，但**它会启动一个内部子事件循环**。如果后台仍有一个串口持续每 `10ms` 疯狂发射数据，子事件循环会被完全填满甚至挤爆内存引发重入与死机。

```diff
    } else {
-     QMessageBox::critical(this, "错误",
-                           "无法打开串口:\n" + m_serial->errorString());
+     QString errorStr = m_serial->errorString();
+     QTimer::singleShot(0, this, [this, errorStr]() {
+       QMessageBox::critical(this, "错误", "无法打开串口:\n" + errorStr);
+     });
      m_btnOpenClose->setChecked(false);
    }
```

将其替换为 `QTimer::singleShot` 后推迟弹窗动作到队列结束，确保了避免模态弹窗和快速后台发送器的信号重连冲突。

2. 打开 **串口 1** 并以 **10ms** 的高频率开启“自动发送”。

4. 在下方新的串口配置中，去故意选 **正在使用中的那个COM口** 并点击“打开串口”。
5. 这时会弹出 `无法打开串口` 的提示，但 **程序绝对不会再卡死无响应**，背后的高速波形和文本接收一切流畅如常。
